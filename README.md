# astrbot_plugin_image_search

简体中文 | [English](README_EN.md)

用于查找图片、插画原始出处及动画截图信息的 AstrBot 插件。

在附图或引用一条带图消息时发送 `/搜图` 查找出处；动画截图可用 `/搜番` 查询名称、集数和时间点。发送 `/搜图帮助` 可查看当前可用渠道和用法，查看帮助不调用模型或搜索服务，也不消耗搜索次数。

## 功能与命令

需要 AstrBot 4.25 及以上的 4.x 版本。加载插件前，在 AstrBot 使用的 Python 环境中安装 `requirements.txt` 里的依赖，然后在插件配置中启用并填写需要的搜索服务：

- SauceNAO：填写 API Key。
- Google Lens：启用后填写 SerpAPI Keys，可填写多个 Key。
- Ascii2d：默认启用，网站要求验证时可填写对应 Cookie。
- trace.moe：默认启用，Token 可留空，使用匿名额度。

命令前缀遵循 AstrBot 设置，下面以 `/` 为例。

| 命令 | 用途 |
| --- | --- |
| `/搜图` | 默认优先 SauceNAO，按配置及结果决定是否补搜或使用备用渠道 |
| `/搜图 g` | 仅用 Google Lens；可用空格或逗号指定多个渠道 |
| `/搜番` | 通过 trace.moe 查询动画名称、集数和时间点 |
| `/搜图 -purge` | 跳过缓存重新搜索 |
| `/搜图帮助` | 查看当前可用渠道、别名及使用方法 |
| `/搜图模式` | 开启连续搜图；可附渠道参数 |
| `/退出搜图模式` | 退出连续模式，不取消正在执行的搜索 |

可以在命令消息中附图、引用一条带图消息，或先发命令再补图，一次可发送多张图片。当前消息和引用消息都有图片时，只搜索当前附图。没有公网地址的图片需要通过 AstrBot 回调文件服务发布，请先配置好该服务。

指定渠道时只搜索所选已启用服务，不追加备用渠道或自动搜番。部分渠道无效时提示并继续有效渠道；全部不可用时不执行搜索。默认搜图只有在 SauceNAO 返回可靠的动画库命中时，才追加 trace.moe 搜番。

已接入 SauceNAO、Google Lens（SerpAPI）、Ascii2d 和 trace.moe；支持 QQ 合并转发及缩略图。Ascii2d 使用 `curl_cffi`，可配置会话及 Cloudflare Cookie，但网站仍可能拒绝访问。SoutuBot 尚未实现。

## 搜索失败与超时

搜索失败时会提示超时、认证失败、额度不足或限频等原因。SauceNAO 和 Google Lens 的提示及插件日志不显示 API Key、图片 URL 或上游错误原文。

Google Lens 遇到认证或额度问题时会尝试下一个 Key，但多个 Key 共用一次搜索的超时，不会按 Key 数延长等待。超时或服务端错误不会触发 Key 切换。请求超时可在“网络”面板调整，默认 30 秒；无效值会使用默认值。

[SerpAPI 已停止支持 products](https://serpapi.com/google-lens-api)。如果曾手动填写此类型，请改为下面列出的有效类型。

## Google Lens 搜索选项

搜索类型：

| 显示名称 | 参数 | 行为 |
| --- | --- | --- |
| 默认搜索 | `all` | 请求综合结果；插件提取其中的图片匹配列表 |
| 相似图片 | `visual_matches` | 查找视觉相似的图片及页面 |
| 完全匹配 | `exact_matches` | 查找包含同一张图片的页面 |

“安全搜索”默认关闭，可选择开启过滤，或使用服务默认设置。对应参数分别为 `safe=off`、`safe=active` 和不发送 `safe`。

## 渠道别名

在各来源服务面板中配置，每项填写一个名称。默认 Google Lens 为 `g`、`谷歌`，SauceNAO 为 `s`，Ascii2d 为 `a`。例如发送 `/搜图 谷歌` 指定 Google Lens。

别名不区分大小写，不能包含命令分隔符或覆盖内置名称；无效或冲突条目会被忽略并记录警告。设置别名不会自动启用渠道。

## LLM 搜图工具

单独发送图片不会向 LLM 提供搜图工具；已进入搜图模式或正在等待补图时，仍由对应命令流程处理。

启用“LLM 工具 → 启用 LLM 搜图工具”后，模型可通过 `search_image` 搜索当前附图或引用图片。工具只提供已启用服务对应的模式：`auto`、`source` 用于找出处，`anime` 用于搜番；未传模式时优先使用 `auto`，只有搜番服务时使用 `anime`。

渠道按当前消息正文确定，未指定时走默认搜索策略，不采用模型自行填写的其他渠道。例如“搜一下谷歌”“搜一下谷歌和 SauceNAO”只搜指定渠道；引用消息中的文字不用于选渠道。提到了渠道但无法准确解析时，会提示改用明确命令，例如 `/搜图 google`，不会猜测或改用其他渠道。

插件先发送搜索结果或失败说明，再由当前会话模型按原有人格简短回复。这仍会产生一次工具完成后的模型续答，不单独调用其他模型生成反馈。模型是否调用工具、是否按要求简短回复，取决于模型表现；搜图命令和自然语言直接搜图不依赖模型调用工具。

## 搜索意图与策略

- `auto`：查找图片来源，仅在渠道返回明确动画信号时追加搜番。
- `source`：只查找图片、插画、作者和页面来源。
- `anime`：查询动画名称、集数和时间点。

默认优先 SauceNAO。低相似度时仅使用配置的补搜渠道，默认不补搜；完全无候选、接口失败或未启用时，仍按 Ascii2d、Google Lens 的备用顺序处理。跳过未启用或未配置的服务。

SauceNAO 最终选择一条候选：Pixiv 候选有 1.03 的评分偏好；相差不足 5 个百分点的 Pixiv 候选优先较小作品 ID。这只是较早投稿的选择策略，不是原创归属证明。Ascii2d 的颜色与特征检索各取首条有效结果，失败相互隔离。Google Lens 保留自身排序及结果数量设置，不混算渠道分数。

## 结果归并

多个渠道命中同一来源链接时，只展示一条结果，并标出各渠道及其相似度。转载页只有明确对应唯一来源时才并入该来源；不会因为标题相同或图片相似就合并，也不会混算不同渠道的分数。

链接去重会识别常见追踪参数和 Pixiv 作品链接的不同写法，其他链接差异仍保留。结果按渠道、标题或作者、缩略图和链接展示；缺失的作者、相似度等信息不补写，有作者主页和来源链接时一并展示。

## 结果发送

“结果展示”面板可设置合并推送触发条数（默认 2，范围 0–10）、是否显示缩略图，以及每张输入图片最多展示的缩略图数（默认 6）。

QQ/aiocqhttp 上，同一张图片找到两条及以上结果时，始终使用合并转发，包括门槛设为 0 时；所有渠道和缓存结果都适用。其余情况按消息条数判断：每张输入图片的结果和提示算一条，图片处理失败提示也算一条。0 不因条数合并，1 始终合并，2–10 达到设定条数时合并。例如默认设置下，两张图片的结果放在同一次转发的两个节点中。
Google 多条匹配共用一个渠道标题，各条按“序号、标题、缩略图、链接”排版，条目之间空行分隔；命中缓存时顶部显示 `Google Lens[缓存]`，各条结果不重复标记，单条匹配不编号。
每个转发节点对应一张输入图片的结果。其他平台按输入图片分别发送普通消息。
图片仅使用渠道提供的缩略图，不下载来源原图；动画成人结果不附预览图。
每张缩略图最多下载 5 秒、3 MiB，最多同时下载 3 张，总等待最多 10 秒。仅接受公网 HTTP(S) 地址的 80/443 端口，跳转后的地址也会检查。
图片失败不丢文字；带图转发失败尝试文字转发，再失败回退普通文字。
缩略图只在本次请求中使用，不保存在磁盘上。

## Ascii2d 使用限制

Ascii2d 仅使用 HTTP 请求；插件不安装浏览器、虚拟显示或操作系统组件。
网站仍可能返回 403/Cloudflare 验证拦截，填写 Cookie 不保证可用。
默认搜图会保留其他渠道的结果并按既有规则继续搜索；显式指定 Ascii2d 时不自动调用未指定渠道。

统一执行基础测试、AstrBot 接口测试和结果发送测试；任一失败返回非零退出码。
QQ 群聊/私聊消息经过实际适配器序列化，但发送动作使用模拟对象，不向 QQ 发消息。

### 转载页来源补全

默认启用“结果展示 → 补全转载页的原始出处”。对没有来源 URL 的 Danbooru、Gelbooru、Konachan、Yande.re 作品页，读取明确的来源字段；成功后展示原出处，并使用原有来源归并规则。不会覆盖已有来源，也不会根据标题或任意页面链接猜测出处。

每次最多解析 6 个不同作品页，同一页只请求一次，额外等待最多 6 秒。403、超时、无来源字段或字段冲突时保留原转载页，不计作搜索渠道失败。关闭此项可取消额外页面请求。仅支持上述站点的已知字段，不保证每个作品都能找到原出处。

只请求作品页 HTML（单页最多 1 MiB），不下载来源原图、不携带网站 Cookie、不递归追踪来源；沿用网络代理配置，拒绝非公网地址及跨作品/跨站跳转。无需安装额外依赖或浏览器。

### 自然语言直接搜图

默认启用“命令交互 → 自然语言直接搜图”。发送“帮我找下出处”“找来源”“找原图”“请帮我搜图”等完整请求，插件会直接搜索，不需要模型决定是否调用工具。可在句尾指定渠道，例如“帮我找下出处 g s”。没有图片时会等待你补图；“搜一下”“搜下”这类省略对象的请求，只有找到附图或引用图片时才直接处理。

常见情况：

| 消息 | 处理方式 |
| --- | --- |
| 图片 + `帮我找下出处` | 直接搜图，不调用 LLM |
| 引用图片 + `找原图 谷歌` | 仅用 Google 搜索引用图片 |
| `请帮我搜图`，随后发图 | 先等待当前用户在当前聊天中补图 |
| `搜一下` | 仅在可解析到图片时直接处理 |
| `怎么搜图`、`如何搜图？`、`搜图怎么用`、`搜图帮助` | 返回当前配置的帮助，不搜索、不计次 |
| `怎么搜番`、`如何搜番`、`搜番怎么用` | 返回同一份帮助；这不是发起搜番 |
| `不要搜图`、`你会搜图吗`、`找出处并分析画风` | 不直接接管，沿用原处理流程 |

帮助问法支持“请问”前缀及句尾标点。以上均遵循会话唤醒条件，不会自动唤醒原本不回复的群聊。

只把当前消息的文字当作请求，引用消息中的文字不参与判断。复杂请求仍交给模型处理，可使用 LLM 搜图工具。关闭此开关不影响搜图命令或 LLM 工具，也不会清空模型的图片上下文。

### 低相似度候选与补搜

SauceNAO 的“最低相似度百分比”默认 60。低于此值的候选不展示，也不触发自动搜番；是否改用其他渠道，由下面的补搜设置决定。

“SauceNAO 相似度过低时自动使用”默认不补搜（`off`），可改为 Ascii2d 或 Google Lens。开启后只尝试所选渠道一次，失败或无结果时不继续增加渠道；所选服务未启用时会提示检查配置。没有可展示结果时，会说明是相似度不足、没有匹配还是请求失败；补搜成功则直接展示结果。

明确指定渠道时不追加补搜。默认搜图、自然语言直接搜图及 LLM 的 `auto`、`source` 模式都使用上述设置。SauceNAO 完全没有候选、请求失败或未启用时，仍依次尝试 Ascii2d、Google Lens 中可用的服务，不受低相似度补搜开关影响。

### 搜索与发送日志

搜索日志记录关联 ID、计划候选与实际调用渠道、结果数量、失败渠道及耗时。结果直接通过 `event.send()` 发送图文或合并转发时，Core 不一定打印 `Prepare to send`；插件记录发送开始、类型、节点数/图片数和直接发送成功。普通文字交给管线时只记录交付，不声称已成功发出。日志不包含图片 URL、标题、API Key 或上游错误原文。

## 缓存、重搜与批量图片

命令、简单自然语言直达和 LLM 工具使用同一套缓存、每日次数及批量处理规则。

- 默认使用有效缓存；`搜图 -purge`、`搜番 -purge`跳过缓存重新搜索。
- `搜图 -purge g s`、`搜图 g -purge s`、`搜图 g s -purge`等价；`-purge` 参数与渠道参数的顺序不影响行为。指定渠道并行执行，输入顺序不控制优先级。
- `-purge` 作用于本次整批图片，Google Lens 同时跳过 SerpAPI 缓存；满足缓存保存条件的新结果覆盖同一缓存键的旧记录；失败或无可靠结果时不覆盖旧记录，也不在本次返回旧缓存。
- LLM 工具使用 `refresh=true` 表示用户明确要求跳过缓存，默认 `false`；一次调用处理整批图片。模型续答会获得处理图片数、缓存图片数及实际外部调用渠道。

“搜索结果缓存”默认开启，有效期 172800 秒（48 小时）。只缓存有结果且没有渠道失败或诊断提示的搜索，不保存模型回复或图片文件。使用缓存时标记 `[缓存]`，展示方式仍按当前配置。

缓存按图片标识、搜索模式、渠道和搜索配置区分。优先使用 OneBot 的稳定图片标识或有效 MD5，无法识别时使用完整 URL，不会额外下载图片来判断是否相同。因此，重复上传的图片如果没有稳定标识且地址发生变化，仍可能重新搜索。

“命令交互 → 每名用户每日搜索次数”默认 30，0 不限；AstrBot 管理员免限额。同一平台连接内的用户跨群聊与私聊合计。每张新搜索的图片预占一次，同图多个渠道、自动补搜只计一次；缓存命中、缺图、渠道全部不可用不扣次数。低相似度候选即使不展示仍计一次；所有渠道均失败或没有任何候选时退回。搜图和搜番共用额度。

次数按 AstrBot 的 `timezone` 设置自然日重置；为空或无效时使用系统时区。计数与缓存集中保存在 `data/plugin_data/astrbot_plugin_image_search/search_state.sqlite3`，插件重载及 AstrBot 重启均保留；卸载时是否删除配置和数据遵循 AstrBot 清理选项。最多保留 1000 条缓存记录，不产生额外图片或日志目录。

“命令交互 → 每次最多搜索图片数”默认 5，可设置为其他正整数。处理当前消息中的图片；当前消息无图时才取引用图片。按顺序逐图搜索，完成后按结果发送规则统一发送，必要时标明所属图片；单张失败不阻止后续图片；不跨图片归并结果。超过上限仅处理前面的图片并提示；次数用尽时停止剩余批次，缓存检查先于限额检查。无图命令收到后续多图消息时同样适用，保留原先指定渠道及`-purge` 参数。

搜索累计超过 3 秒还未完成时，会提示“正在搜索，请稍候。”，一批最多提示一次；读取缓存和发送结果的等待时间不计入这 3 秒。超时按每次服务请求计算，不是整批搜索的总时限。搜图模式会跳过仍在处理的重复图片，普通命令和 LLM 工具暂不做这项去重。

## 搜索日志

排查问题时，可用请求 `id` 找到同一次搜索的记录；`id/1`、`id/2` 对应批次中的图片。日志记录缓存是否命中、缓存年龄及图片和搜索条件的指纹，不输出图片 URL 或配置原文。指纹是截短的 SHA-256 摘要：地址指纹变化只说明 URL 变了，不能证明图片被重新压缩；条件指纹变化说明模式、渠道或搜索配置变了。“无有效记录”可能是没有缓存、已过期或记录损坏，日志不进一步区分。

搜索完成分别记录归并后的结果数、原始条目数、低相似度过滤及失败渠道；缓存命中不记为外部搜索。发送记录分别显示结果数、合并门槛、卡片数与缩略图数，门槛按普通消息数量计算，随结果附带的提示不额外计数。请求结束汇总缓存图片、外部搜索图片、无结果与跳过或失败图片；“交由普通文字发送”表示已交给 AstrBot 发送流程，不代表平台已经送达。

## 连续搜图模式

要连续查多张图片，可以发送 `/搜图模式`，随后只发图片即可，不必每次输入命令。模式仅对当前聊天中的你生效，支持一次多图；带文字或引用的消息不会由模式自动搜索。此功能默认启用，可在“搜图模式”面板关闭，不影响普通搜图命令。

- `搜图模式 g`：开启或切换至 Google；渠道别名和多渠道选择与搜图命令相同。
- 再次发送 `搜图模式`：恢复默认渠道并续期。
- `退出搜图模式`：关闭；不取消已经开始的搜索或单次等待。模式开启期间，同一用户在当前会话发送纯文字整句 `结束搜图`、`退出搜图`、`结束`、`退出` 也可关闭，不经过 LLM；未开启时不接管这些短语，不匹配句子中的部分文字。
- 默认空闲 60 秒自动退出并提示；每次收到纯图片消息续期。群聊和私聊均适用，可在“搜图模式 → 空闲退出秒数”调整为 10–3600 秒。
- 缓存、每日限额、批量上限、结果展示均复用普通搜图，不经过 LLM。刷新仍使用单次 `搜图 -purge`，不把刷新参数保存在模式中。
- 无图搜图命令的单次等待优先接收图片；等待期间不能新开启搜图模式。模式只保存在内存，插件重载或 AstrBot 重启后关闭，不额外发送退出提示。

模式会跳过同一消息中的重复图片，以及你在当前聊天、相同渠道下仍在搜索的图片，不重复计次或发送结果。去重使用稳定图片标识或完整 URL，不下载图片比较内容。搜索完成后再次发图仍可正常搜索或读取缓存；直接使用搜图命令和 `-purge` 不受模式去重限制。不同用户、聊天之间不共享正在搜索的结果。模式日志记录开启、渠道切换、重复跳过和退出等状态，使用用户指纹关联，不记录原始用户标识。
